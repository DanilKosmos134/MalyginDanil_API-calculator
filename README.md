# API Калькулятор с CI/CD и безопасностью

Этот проект представляет собой API-калькулятор, написанный на Python с использованием FastAPI. Проект упакован в Docker-контейнер, а для него настроен пайплайн непрерывной интеграции (CI/CD) с внедренными инструментами безопасности.

## 🛠 Технологии
* **Python** (FastAPI, Uvicorn)
* **Docker**
* **GitHub Actions** (CI/CD)
* **Semgrep** (Статический анализ кода / SAST)
* **Trivy** (Сканирование уязвимостей Docker-образов)

## 🚀 Как запустить локально
1. Собрать Docker-образ:
   ```bash
   docker build -t calculator-api:v1 .

2. Запустить контейнер (на порту 8000):

(Примечание: внутри контейнера приложение всегда работает на порту 8000. Я "пробросил" его на внешний порт 20000, так как порт 8000 у меня на Windows был занят).

    ```bash
    docker run -d -p 8000:8000 --name my-calculator calculator-api:v1

3. Открыть в браузере интерактивную документацию Swagger UI:
    http://127.0.0.1:20000/docs

## 🛡 Безопасность (Пайплайн)
При каждом пуше в ветку main автоматически запускается GitHub Actions, который:

1. Проверяет код на уязвимости с помощью Semgrep.
2. Собирает Docker-образ.
3. Сканирует образ на известные CVE-уязвимости с помощью Trivy.
4. Результаты проверок доступны во вкладке Actions данного репозитория.

## 🛡 Анализ уязвимостей (Пайплайн)
В рамках пайплайна были интегрированы два инструмента: Semgrep (статический анализ кода) и Trivy (сканирование Docker-образов).

1. Отчет Semgrep:
Инструмент просканировал 6 файлов (1074 правила) и нашел 2 уязвимости (2 blocking) в файле конфигурации CI/CD пайплайна (ci.yml).

Проблема: Использование изменяемых тегов (actions/checkout@v3 и aquasecurity/trivy-action@master). Это создает риск Supply Chain атаки (если злоумышленник скомпрометирует репозиторий действия, он сможет выполнить свой код в нашем пайплайне).

Предложение по улучшению: Закрепить используемые действия на конкретных хэшах коммитов (40-символьный SHA) вместо плавающих тегов.

2. Отчет Trivy (сканер контейнеров):
При сканировании собранного Docker-образа было найдено 2 уязвимости уровня HIGH в базовых пакетах Python.

Проблема 1: CVE-2026-23949 в библиотеке jaraco.context (Path traversal). Исправлено в версии 6.1.0.

Проблема 2: CVE-2026-24049 в библиотеке wheel (Выполнение произвольного кода / Повышение привилегий). Исправлено в версии 0.46.2.

Предложение по улучшению: Для устранения данных уязвимостей необходимо добавить в Dockerfile шаг обновления базовых пакетов сборки (например, RUN pip install --upgrade setuptools wheel) перед установкой основных зависимостей, либо использовать более свежий базовый образ.
